====================================================
KoreanTTS.exe 빌드 방법
====================================================

KoreanTTS.exe 는 gui.py 를 PyInstaller 로 패키징한 것입니다. 다시 빌드해야
할 때 (korean_tts.py 나 gui.py 를 고친 뒤, 또는 sound/ 파일을 바꾼 뒤)
아래 명령을 그대로 실행하면 됩니다.

1) 준비 (한 번만)
------------------
    py -m pip install pyinstaller

2) 빌드
--------
이 폴더(Allinone (2))에서 실행하세요:

    py -m PyInstaller --onefile --windowed --name KoreanTTS ^
        --add-data "sound;sound" ^
        --distpath . --workpath build_temp --specpath build_temp ^
        --noconfirm gui.py

    (PowerShell 에서 여러 줄로 나눠 쓰려면 줄 끝에 ^ 대신 백틱(`)을 씁니다.
    한 줄로 이어 써도 됩니다.)

빌드가 끝나면 KoreanTTS.exe 가 이 폴더에 바로 생깁니다 (dist/ 폴더 안이
아니라 --distpath . 로 지정했기 때문). build_temp/ 는 중간 빌드 파일이라
지워도 안전합니다.

이 폴더에 .exe 를 두는 이유
----------------------------
gui.py 의 "고급 설정" 탭에서 저장하는 sound_overrides.json 은 exe 파일
바로 옆에 저장됩니다 (임시로 압축 해제되는 폴더가 아니라, 실행할 때마다
없어지지 않는 위치). tts.py 가 sound_overrides.json 을 찾는 기본 위치도
바로 이 폴더이므로, KoreanTTS.exe 를 이 폴더에 그대로 두면 exe 에서 한
미세조정이 py tts.py 실행에도 자동으로 적용됩니다. exe 를 다른 폴더로
옮기면 그쪽 폴더에 새로 sound_overrides.json 이 생기고, tts.py 는 여전히
이 폴더의 것을 보므로 서로 다른 설정이 됩니다 - 그래서 옮기지 않는 것을
권장합니다. 정말 옮겨야 한다면, sound_overrides.json 파일을 tts.py 가
있는 폴더로 복사해오면 됩니다.

고급 설정 탭에 있는 기능들
--------------------------
- 파형 보기: 선택한 음성 조각의 파형을 직접 보면서 자르기 시작/끝 지점을
  마우스로 드래그해서 조절할 수 있습니다 (ms 슬라이더도 그대로 있고 서로
  연동됩니다).
- 원본/조정본 미리듣기: 자동 처리만 된 원본과, 지금 만지고 있는 조정본을
  번갈아 들어보며 비교할 수 있습니다.
- 이음매 타이밍 고급 설정: 음량/자르기 외에, 이 조각이 관여하는 교차
  길이(crossfade_ms), 받침 길이(coda_max_ms, ㄴㄹㅁㅇ 전용), 받침 뒤
  간격(stop_gap_ms, 이 조각이 ㄱㄷㅂ받침으로 끝날 때)까지 조각별로 따로
  지정할 수 있습니다. 체크박스를 켜야 그 값이 저장되고, 꺼두면 전역 기본
  설정을 그대로 따릅니다.
- 내보내기/가져오기: 지금까지 만든 미세조정 설정을 다른 파일로 저장하거나
  (백업/공유용), 다른 곳에서 만든 설정 파일을 불러올 수 있습니다 (병합
  또는 전체 교체 선택 가능).

일괄 변환 탭
------------
텍스트 파일(한 줄에 한 문장)을 불러오거나 직접 여러 줄을 입력한 뒤, 출력
폴더를 고르고 "전체 변환"을 누르면 문장마다 001_문장.wav 형식으로 WAV
파일을 한 번에 만들어줍니다. 재생 탭의 설정(속도/간격/볼륨/받침 뒤 간격)과
고급 설정 탭에서 저장한 조각별 미세조정이 그대로 적용됩니다.

확인한 사항
------------
- 빌드된 exe 를 직접 실행해서 5초 이상 정상적으로 떠 있는 것을 확인
  (기능 추가 후 다시 빌드해서 재확인함).
- exe 실행 중 실제로 생기는 임시 압축 해제 폴더 안에서 sound/ 의 268개
  .wav 파일이 전부 들어있는 것을 확인.
- "얼린(frozen)" 상태를 흉내 낸 테스트로, 설정/미세조정 파일이 (없어지는)
  임시 폴더가 아니라 exe 옆에 정확히 저장되는 것을 코드로 확인.
- 새 고급 설정(crossfade_ms/coda_max_ms/stop_gap_ms)이 korean_tts.py의
  build_audio에서 정확히 반영되는 것을 실제 오디오 길이 차이로 직접 계산
  검증함 (예: stop_gap_ms를 40->300으로 올리면 정확히 그 차이만큼(ms 단위
  샘플 수) 오디오가 길어짐). 같은 설정 파일을 tts.py --overrides 로 읽었을
  때도 동일하게 반영되는 것을 CLI로 직접 확인함 - GUI/CLI가 같은
  sound_overrides.json 형식을 공유하므로 자동으로 호환됨.
- 파형 편집기의 드래그 클램핑(시작/끝 마커가 서로 교차하지 않는 것), 파일명
  정리 함수(금지 문자 제거, 빈 줄은 "untitled"로 대체), 일괄 변환의 빈 줄
  필터링과 파일 저장을 Python에서 직접 호출해 코드로 검증함.
- 화면을 직접 눌러보며 사용하는 테스트(마우스 클릭/드래그 등 실제 상호작용)
  는 이 환경에서 GUI 이벤트 루프를 오래 띄워두기 어려워 하지 못했습니다 -
  처음 실행할 때 버튼/슬라이더/드래그가 실제로 기대대로 동작하는지 한 번
  확인해보세요.

자동 빌드 (GitHub Releases)
----------------------------
이 저장소를 GitHub에 올려두면, 위 명령을 손으로 칠 필요 없이
.github/workflows/release.yml 이 자동으로 KoreanTTS.exe 와 Android APK를
빌드해서 GitHub Release 초안(draft)으로 올려줍니다.

    git tag v1.0.0
    git push origin v1.0.0

또는 GitHub 저장소 페이지 -> Actions -> Release -> Run workflow 에서
태그 이름을 직접 입력해도 됩니다 (그 태그가 없으면 새로 만들어줍니다).
초안(draft) 상태로 생성되니, Releases 페이지에서 첨부 파일과 설명을
확인한 뒤 직접 "Publish release"를 눌러야 실제로 공개됩니다.
