====================================================
한국어 CLI TTS - tts.py
====================================================

디스코드 없이 터미널에서 한글 텍스트를 바로 읽게 하는 프로그램입니다.
설치할 패키지가 없습니다. FFmpeg 도 필요 없습니다. 파이썬 표준 라이브러리
만으로 동작합니다 (jamo, numpy, audioop 등 아무것도 설치하지 않아도 됩니다).

필요한 것: 파이썬 3.8 이상, 그리고 이 폴더의 sound/ (음성 조각 268개, .wav).


1) 실행
--------
    py tts.py 안녕하세요               텍스트를 바로 재생
    py tts.py -o 인사.wav 안녕하세요    파일로 저장 (재생하지 않음)
    py tts.py -p 국물이 좋다           실제 발음만 텍스트로 보기: '궁무리 조타'
    py tts.py -s 안녕하세요            재생 없이 어떤 음성 조각을 쓰는지 보기
    py tts.py --speed 1.5 안녕하세요   1.5배 빠르게 재생 (0.5~2.0)
    py tts.py --stop-gap 80 학교        받침 ㄱㄷㅂ 뒤에 80ms 더 쉬고 다음 글자 읽기
    py tts.py                          대화형 모드 (문장을 계속 입력)
    py tts.py --check                  sound/ 에 빠진 파일이 있는지 점검


2) 옵션
--------
    -o, --output FILE   재생 대신 지정한 .wav 파일로 저장
    -p, --pronounce     연음/비음화/격음화 등이 적용된 실제 발음을 출력
                        (단독 사용 시 재생하지 않음, -o 와 같이 쓰면 저장은 됨)
    -s, --show          사용되는 음성 조각 이름을 출력 (단독 사용 시 재생하지 않음)
    --gap MS            띄어쓰기/문장부호에서 쉬는 길이, 기본 300ms
    --fade MS           조각 이음새를 부드럽게, 기본 5ms (0이면 끔)
    --no-normalize      음량 자동 보정을 끄고 원본 음량 그대로 재생/저장
    --no-crossfade      이중모음/받침 크로스페이드를 끄고 조각을 그대로 이어붙임
    --speed X           재생 속도 배율, 기본 1.0 (0.5~2.0로 자동 제한)
                        속도를 바꾸면 음높이도 함께 바뀝니다 (테이프 배속처럼) -
                        음높이는 그대로 두고 속도만 바꾸려면 별도의 라이브러리가
                        필요해서, 무의존성을 유지하기 위한 의도적인 절충입니다.
                        (안드로이드 앱은 OS 기능으로 음높이를 유지한 채
                        속도만 바꿉니다 - 아래 안드로이드 앱 설명 참고)
    --stop-gap MS       받침 ㄱ/ㄷ/ㅂ(ㅋ,ㄲ,ㅌ 등 이 셋으로 합쳐지는 받침 전부
                        포함) 뒤에서 다음 글자로 넘어가기 전 추가로 쉬는
                        길이, 기본 40ms (0이면 끔). 그 외 받침(ㄴㄹㅁㅇ)
                        이나 받침 없는 글자 사이에는 적용되지 않습니다.
    --overrides FILE    음성 조각별 미세조정 파일 위치, 기본 ./sound_overrides.json
                        (데스크톱 앱 KoreanTTS.exe 의 "고급 설정" 탭에서 저장한
                        파일을 그대로 읽습니다 - 음량 보정/자르기 외에도
                        조각별 교차 길이/받침 길이/받침 뒤 간격까지 지정할 수
                        있습니다. 자세한 형식은 korean_tts.py 상단의
                        "Per-sample fine-tuning overrides" 주석 참고)
    --no-overrides      음성 조각별 미세조정 파일을 무시하고 자동 처리 결과만 사용
    --sound-dir DIR     음성 파일 폴더 위치 지정 (기본 ./sound)
    --check             빠진 음성 파일을 점검하고 종료


3) 대화형 모드
---------------
인자 없이 py tts.py 만 실행하면 문장을 계속 입력할 수 있는 모드로 들어갑니다.

    :q            종료
    :show         쓰인 음성 조각 순서 표시 켜기/끄기
    :pron         실제 발음 표시 켜기/끄기
    :norm         음량 자동 보정 켜기/끄기
    :cross        크로스페이드 켜기/끄기
    :speed 1.5    재생 속도를 1.5배로 바꾸기 (0.5~2.0)
    :stopgap 80   받침 ㄱㄷㅂ 뒤 간격을 80ms로 바꾸기 (기본 40, 0이면 끔)
    :gap 200      쉼 길이를 200ms로 바꾸기
    :save out.wav 방금 입력한 문장을 파일로 저장


====================================================
자연스러운 발음 처리
====================================================

글자 하나하나를 따로 읽지 않고, 앞뒤 글자가 만날 때 실제로 어떻게 소리 나는지
표준 발음법대로 처리합니다. -p 옵션으로 실제 어떻게 발음될지 텍스트로 미리
확인할 수 있고, 규칙은 한 문장 안에서 여러 개가 이어서 적용됩니다
(예: 협력을 -> 혐녀글, 국물이 -> 궁무리).

연음화 (받침이 뒤 모음으로 이동)
    옷이     -> 오시   (받침 ㅅ이 다음 음절로 이동)
    좋아요   -> 조아요  (받침 ㅎ은 모음 앞에서 사라짐)
    값이     -> 갑시   (겹받침은 둘로 나뉘어 하나씩 처리)
    강아지   -> 강아지 (받침 ㅇ은 다음 음절로 넘어가지 않음, 원래 그대로)

비음화 (받침 ㄱㄷㅂ + ㄴㅁ -> ㅇㄴㅁ)
    국물     -> 궁물
    밥물     -> 밤물
    닫는다   -> 단는다

ㄹ 관련 비음화 · 유음화
    협력     -> 혐녁   (받침 ㄱㄷㅂ + ㄹ -> 둘 다 비음화)
    담력     -> 담녁   (받침 ㅁㅇ + ㄹ -> ㄹ만 ㄴ으로)
    신라     -> 실라   (ㄴ+ㄹ / ㄹ+ㄴ -> ㄹㄹ, 일반적인 경우만)

격음화 (ㅎ + 예사소리 -> 거센소리)
    좋다     -> 조타
    많고     -> 만코
    각하     -> 가카

경음화 (받침 ㄱㄷㅂ 뒤 예사소리 -> 된소리)
    국밥     -> 국빱
    학교     -> 학꾜
    학생     -> 학쌩
    잡지     -> 잡찌

ㅈㅉㅊ 뒤 반모음 탈락 (한 음절 안에서 판단, 앞뒤 글자 필요 없음)
    가져요   -> 가저요
    쟤       -> 재
    다쳤어요 -> 다처써요
    (ㅈ,ㅉ,ㅊ은 이미 구개음이라 뒤에 오는 ㅑㅒㅕㅖㅛㅠ의 반모음이 따로
     들리지 않습니다 - 표준발음법 제5항 다만1)

ㅢ의 단모음화 (한 음절 안에서 판단)
    희망     -> 히망
    무늬     -> 무니
    띄어쓰기 -> 띠어쓰기
    의사     -> 의사   (첫소리가 ㅇ이면 그대로, 표준발음법 제5항 다만3)

띄어쓰기나 문장부호를 사이에 두면 위 규칙 중 앞뒤 글자가 만나야 적용되는
것들(연음화/비음화/유음화/격음화/경음화)은 적용되지 않습니다 (실제 발음
규칙과 동일). ㅈㅉㅊ 뒤 반모음 탈락과 ㅢ의 단모음화는 한 글자 안에서만
판단하므로 이 제약과 무관하게 항상 적용됩니다.

다루지 않는 규칙 (사전/형태소 정보가 있어야 판단 가능한 것들)
    - 구개음화: 굳이 -> 구지 는 처리되어야 하지만 마디(형태소 경계가 없는
      단어) 는 구지로 잘못 바뀌면 안 되는데, 표면 글자만 보고는 구별할 수
      없습니다.
    - 사잇소리 경음화: 손+가락 -> 손까락 같은 경우. 받침이 ㄱㄷㅂ이 아니라
      합성어라는 정보가 있어야 판단 가능합니다.
    - 유음화의 한자어 예외: 의견란 -> 의견난 (의결란이 아님) 같은 경우.

이 규칙들을 직접 구현하기 전에 파이썬 라이브러리 korean_romanizer 를 검토해
봤습니다 (순수 파이썬이라 g2pK처럼 자바/mecab이 필요 없어서 유력한 후보였음).
실제로 설치해서 테스트해보니 비음화(국물 -> 국물, 안 바뀜)가 아예 빠져 있고
구개음화는 틀리게 구현되어 있었습니다(해돋이 -> 해도디, 해도지가 맞음). 격음화만
정확히 동작했습니다. 이런 이유로 검증 가능한 규칙만 직접 만들어 넣는 쪽을
택했습니다.


====================================================
음질 처리
====================================================

음량 자동 보정
--------------
sound 폴더의 268개 파일은 녹음 상태가 제각각이라 RMS 음량 기준으로 최대
45배까지 차이가 났습니다 (어떤 글자는 거의 안 들리고 어떤 글자는 상대적으로
큼). 재생/저장 시 각 조각을 기본적으로 음량 정규화합니다:

    - 목표 음량(RMS)에 맞춰 조용한 조각은 키우고 큰 조각은 줄입니다.
    - 너무 조용한 조각(짧은 무음/노이즈)을 과하게 키워 잡음이 커지지 않도록
      증폭 배율에 상한을 둡니다.
    - 이미 큰 조각을 키우다 클리핑(찢어짐)되지 않도록 피크 상한도 둡니다.
    - 각 조각 앞뒤의 무음 구간도 잘라내어, 이어붙였을 때 쉬는 길이가
      --gap 값 그대로 나오도록 합니다.

목표 음량은 기본적으로 꽤 높게 잡혀 있습니다 (원래보다 +4dB 더 큼 - 268개
파일 중 조용한 쪽 3%(예: beu.wav) 정도만 증폭 배율 상한에 걸려 목표보다
조금 작게 나오고, 나머지는 목표 음량에 맞춰집니다). 대부분의 기기에서
음량을 따로 올리지 않아도 잘 들리도록 하기 위한 것입니다.

원본 그대로 듣고 싶으면 --no-normalize (대화형은 :norm) 로 끌 수 있습니다.

이중모음·받침 크로스페이드
--------------------------
sound 폴더에는 "초성+모음" 조각과 "모음+예사받침" 조각(예: 압 -> "ab" 하나)만
녹음되어 있고, 이중모음(ㅘㅝㅢ 등)이나 유성 받침(ㄴㄹㅁㅇ)은 그런 조각이 없어서
대신 다른 조각 두 개를 이어 붙입니다. 문제는 유성 받침용 낱글자 조각("n","m",
"l","ng")이 원래 온전한 한 음절 길이(150~230ms)로 녹음되어 있어서, 그냥 이어
붙이면 그 글자 하나가 음절 두 개 분량으로 늘어져 들립니다.

    화 -> "ho"+"a" 를 그냥 이어 붙이면 380ms, 실제로는 한 음절이어야 함
    안 -> "a"+"n"  마찬가지로 490ms

한 글자를 이루는 조각들은 그냥 이어 붙이지 않고 겹쳐서 크로스페이드 합니다
(뒤 조각의 시작과 앞 조각의 끝을 등강도(equal-power) 곡선으로 섞어 자연스럽게
이어지면서 전체 길이도 줄어듭니다):

    - 이중모음(ㅘ/ㅝ/ㅢ 등): 짧은 쪽 길이의 50%까지 겹침 - 모음 두 개가
      섞이는 게 실제 이중모음이 소리 나는 방식과 같아서 더 과감하게 섞습니다.
    - 유성 받침(ㄴㄹㅁㅇ): 짧은 쪽 길이의 25%까지 겹침 - 받침 자음의 특징이
      묻히지 않도록 이중모음보다는 살짝만 섞습니다.
    - 예사받침이 이미 모음과 한 조각으로 녹음된 경우(학 -> "ha"+"ag" 등)는
      원래 문제가 없던 경우라 건드리지 않습니다.

유성 받침 낱글자 조각("n","l","m","ng")은 크로스페이드만으로는 부족할 만큼
길어서, 받침으로 쓰일 때는 재생 전에 80ms로 잘라내고 그 끝을 짧게
페이드아웃합니다. 받침은 모음 뒤에서 뒷모음 없이 바로 끝나야 하므로, 원본을
그대로 쓰는 대신 이렇게 짧은 닫힘 소리만 남깁니다.

크로스페이드 + 받침 자르기를 합치면 실측 기준:

    안 493ms -> 322ms (35%)     반 494ms -> 323ms (35%)
    왕 765ms -> 445ms (42%)     웜 703ms -> 444ms (37%)
    화 382ms -> 322ms (16%, 이중모음만 해당, 받침 없음)

--no-crossfade (대화형은 :cross) 로 끄면 크로스페이드와 받침 자르기를 모두
끄고 예전처럼 그냥 이어 붙입니다. 비율/길이는 korean_tts.py 의
CROSSFADE_FRACTION, CODA_MAX_MS 에서 조정할 수 있습니다.

받침 ㄱㄷㅂ 뒤 간격
--------------------
위의 크로스페이드/받침 자르기가 "너무 긴" 받침(ㄴㄹㅁㅇ) 문제를 다룬다면,
이건 반대 문제입니다: 받침 ㄱ/ㄷ/ㅂ(대표음 기준 - ㅋ,ㄲ,ㅅ,ㅆ,ㅈ,ㅊ,ㅌ,ㅎ,ㅍ
등도 전부 이 셋 중 하나로 합쳐짐)으로 끝나는 글자는 다음 글자로 너무 빨리
넘어가서 급하게 들립니다. 실제 발음에서는 이 받침들이 파열 없이 닫힌
채로 잠깐 멈췄다가 다음 소리로 넘어가는데, 지금까지는 다른 글자 사이와
똑같이 간격 없이 바로 이어 붙이고 있었습니다.

기본적으로 이런 받침 뒤에 40ms 를 추가로 쉬고 다음 글자를 읽습니다
(--stop-gap, 대화형 :stopgap 으로 0~200ms 사이에서 조절, 0이면 끔).
연음화·비음화·경음화 등으로 받침의 실제 발음이 바뀐 경우(예: 국물 ->
궁물, ㄱ이 비음화되어 ㅇ이 됨)에는 바뀐 뒤의 발음 기준으로 판단하므로,
받침이 사라지거나 다른 받침으로 바뀐 경우에는 이 간격이 붙지 않습니다.


====================================================
문제 해결
====================================================

"음성 폴더가 없습니다" 라고 나올 때
    sound.zip 을 이 폴더 안 sound/ 에 풀었는지 확인하세요.
    다른 위치에 있다면 --sound-dir 로 경로를 지정하세요.

한글이 깨져서 나올 때 (cmd 창)
    chcp 65001 을 먼저 실행해서 콘솔 코드페이지를 UTF-8로 바꾸세요.
    (프로그램 자체는 깨진 글자 없이 항상 정상적으로 동작합니다 - 화면
    출력만 깨져 보이는 문제입니다)

재생이 안 될 때
    Windows 는 winsound 로 재생하므로 별도 설치가 필요 없습니다. 다른
    OS 에서는 ffplay(ffmpeg), aplay, paplay 중 하나가 PATH 에 있어야
    합니다. 재생 대신 -o 로 파일만 저장해서 다른 플레이어로 들어도 됩니다.

특정 글자가 안 들릴 때
    py tts.py --check 로 sound/ 에 필요한 268개 조각이 다 있는지
    확인하세요. 빠진 파일이 있으면 목록으로 알려줍니다.


====================================================
파일 구성
====================================================

    korean_tts.py   한글 -> 발음 처리 -> 음성조각 변환 -> wav 합치기.
                    디스코드 봇(main.py)과 이 로직을 공유합니다.
    sound/          음성 조각 268개 (.wav)

발음/조각 변환 규칙과 음질 처리는 korean_tts.py 한 곳에만 있어서, 봇과
CLI 가 항상 똑같이 발음하고 똑같이 들립니다. 디스코드 봇 자체의 설치·실행
