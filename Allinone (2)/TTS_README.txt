====================================================
한국어 CLI TTS - tts.py
====================================================

디스코드 없이 터미널에서 한글 텍스트를 바로 읽게 하는 프로그램입니다.
설치할 패키지가 없습니다. FFmpeg 도 필요 없습니다. 파이썬 표준 라이브러리
만으로 동작합니다 (jamo, numpy, audioop 등 아무것도 설치하지 않아도 됩니다).

필요한 것: 파이썬 3.8 이상, 그리고 이 폴더의 sound/ (음성 조각 268개, .wav).


1) 실행
--------
    py tts.py 안녕하세요               텍스트를 바로 재생
    py tts.py -o 인사.wav 안녕하세요    파일로 저장 (재생하지 않음)
    py tts.py -p 국물이 좋다           실제 발음만 텍스트로 보기: '궁무리 조타'
    py tts.py -s 안녕하세요            재생 없이 어떤 음성 조각을 쓰는지 보기
    py tts.py --speed 1.5 안녕하세요   1.5배 빠르게 재생 (0.5~2.0)
    py tts.py --stop-gap 80 학교        받침 ㄱㄷㅂ 뒤에 80ms 더 쉬고 다음 글자 읽기
    py tts.py                          대화형 모드 (문장을 계속 입력)
    py tts.py --check                  sound/ 에 빠진 파일이 있는지 점검


2) 옵션
--------
    -o, --output FILE   재생 대신 지정한 .wav 파일로 저장
    -p, --pronounce     연음/비음화/격음화 등이 적용된 실제 발음을 출력
                        (단독 사용 시 재생하지 않음, -o 와 같이 쓰면 저장은 됨)
    -s, --show          사용되는 음성 조각 이름을 출력 (단독 사용 시 재생하지 않음)
    --gap MS            띄어쓰기/문장부호에서 쉬는 길이, 기본 300ms
    --fade MS           조각 이음새를 부드럽게, 기본 5ms (0이면 끔)
    --no-normalize      음량 자동 보정을 끄고 원본 음량 그대로 재생/저장
    --no-crossfade      이중모음/받침 크로스페이드를 끄고 조각을 그대로 이어붙임
    --speed X           재생 속도 배율, 기본 1.0 (0.5~2.0로 자동 제한)
                        속도를 바꾸면 음높이도 함께 바뀝니다 (테이프 배속처럼) -
                        음높이는 그대로 두고 속도만 바꾸려면 별도의 라이브러리가
                        필요해서, 무의존성을 유지하기 위한 의도적인 절충입니다.
                        (안드로이드 앱은 OS 기능으로 음높이를 유지한 채
                        속도만 바꿉니다 - 아래 안드로이드 앱 설명 참고)
    --stop-gap MS       받침 ㄱ/ㄷ/ㅂ(ㅋ,ㄲ,ㅌ 등 이 셋으로 합쳐지는 받침 전부
                        포함) 뒤에서 다음 글자로 넘어가기 전 추가로 쉬는
                        길이, 기본 40ms (0이면 끔). 그 외 받침(ㄴㄹㅁㅇ)
                        이나 받침 없는 글자 사이에는 적용되지 않습니다.
    --overrides FILE    음성 조각별 미세조정 파일 위치, 기본 ./sound_overrides.json
                        (데스크톱 앱 KoreanTTS.exe 의 "고급 설정" 탭에서 저장한
                        파일을 그대로 읽습니다 - 음량 보정/자르기 외에도
                        조각별 교차 길이/받침 길이/받침 뒤 간격까지 지정할 수
                        있습니다. 자세한 형식은 korean_tts.py 상단의
                        "Per-sample fine-tuning overrides" 주석 참고)
    --no-overrides      음성 조각별 미세조정 파일을 무시하고 자동 처리 결과만 사용
    --sound-dir DIR     음성 파일 폴더 위치 지정 (기본 ./sound)
    --voice NAME        사용할 목소리, 기본 'default' (아래 "여러 목소리" 참고)
    --list-voices       사용 가능한 목소리 목록을 출력하고 종료
    --check             빠진 음성 파일을 점검하고 종료


3) 대화형 모드
---------------
인자 없이 py tts.py 만 실행하면 문장을 계속 입력할 수 있는 모드로 들어갑니다.

    :q            종료
    :show         쓰인 음성 조각 순서 표시 켜기/끄기
    :pron         실제 발음 표시 켜기/끄기
    :norm         음량 자동 보정 켜기/끄기
    :cross        크로스페이드 켜기/끄기
    :speed 1.5    재생 속도를 1.5배로 바꾸기 (0.5~2.0)
    :stopgap 80   받침 ㄱㄷㅂ 뒤 간격을 80ms로 바꾸기 (기본 40, 0이면 끔)
    :gap 200      쉼 길이를 200ms로 바꾸기
    :voice NAME   목소리 바꾸기
    :voices       사용 가능한 목소리 목록 보기
    :save out.wav 방금 입력한 문장을 파일로 저장


4-1) 여러 목소리 (multi-voice)
-------------------------------
목소리마다 sound/ 안에 자기 이름의 폴더가 하나씩 있습니다 - 원래
목소리도 sound/default/ 입니다. 다른 목소리를 추가하려면 sound/ 안에
새 폴더를 만들고 (예: sound/narrator2/) 같은 파일 이름(ga.wav, ab.wav,
...)으로 녹음을 채워 넣으면 됩니다 (VoiceRecorder.exe 를 쓰면 이 폴더
구조로 바로 저장해줍니다 - VOICE_RECORDER_README.txt 참고). 일부만
채워도 되고, 없는 파일은 다른 파일들과 마찬가지로 "없음"으로 보고되고
건너뜁니다.

    py tts.py --list-voices                사용 가능한 목소리 목록
    py tts.py --voice narrator2 안녕하세요   그 목소리로 재생
    py tts.py --voice narrator2 --check     그 목소리에서 빠진 파일 점검

음성 조각별 미세조정(--overrides, 고급 설정 GUI)도 목소리별로 따로
저장됩니다: default는 지금처럼 sound_overrides.json, 다른 목소리는
sound_overrides.<목소리이름>.json 파일을 씁니다. 자동으로 나뉘므로
따로 신경 쓸 필요는 없습니다.

새 목소리를 추가했다면 sync-sound-assets.bat 을 다시 실행해야
Android 앱과 웹 버전에도 반영됩니다 (해당 스크립트 안내 참고).

목소리 폴더 이름은 영문/숫자로 (예: narrator2) - 안드로이드는 밑줄(_)이나
마침표(.)로 시작하는 assets 폴더를 빌드 시 자동으로 빼버리기 때문에,
그런 이름을 쓰면 CLI/데스크톱에서는 보이는데 Android 앱에서만 안 보이는
혼란스러운 상황이 생깁니다.


4-2) 사운드 뱅크 종류 (bank.json)
----------------------------------
목소리 폴더 안에 bank.json 파일을 두면 그 목소리가 어떤 방식으로
녹음되어 있는지 지정할 수 있습니다. 파일이 없으면 지금까지와 완전히
똑같이 "조각 방식"으로 동작합니다 - 기존 목소리는 아무것도 바꿀 필요가
없습니다.

    {
      "schema_version": 1,
      "type": "pieces",
      "settings": {},
      "audio": {}
    }

현재 세 가지 종류를 지원합니다:

  pieces (기본값, bank.json이 없을 때와 동일)
      지금까지 쓰던 253개 조각(초성+모음, 모음+받침 등) 방식입니다.
      settings로 아래 두 가지를 추가로 켤 수 있습니다 (둘 다 기본은
      꺼짐이고, VoiceRecorder.exe 새 목소리 만들기 화면의 "고급 설정"
      체크박스로도 켤 수 있습니다):

      "dedicated_diphthongs": true
          이중모음이 들어간 음절(예: 과, 왕, 확)에 대해 별도로 녹음한
          파일이 있는지 먼저 찾아보고, 있으면 그걸 쓰고 없으면
          지금처럼 두 조각을 이어붙입니다. 받침 종류에 따라 다르게
          동작합니다:
            - 받침 없음(예: 과): 그 글자 자체(과)의 녹음을 그대로 씀.
            - 받침 ㄴㄹㅁㅇ(예: 왕): 받침 없는 이중모음(와)의 녹음 +
              공용 받침 조각(ng 등)을 이어붙임 - 받침만 기존 방식.
            - 받침 ㄱㄷㅂ(예: 확): 그 글자 전체(확)를 통째로 녹음한
              파일이 있으면 그걸 그대로 쓰고, 없지만 받침 없는
              이중모음(화)은 녹음되어 있으면 그것과 일반 조각
              방식에서 쓰는 모음+받침 조각(예: 확이면 "ag" - 악의
              조각)을 이어붙입니다. 이러면 "화"를 한 번만 녹음해도
              화+ㄱ/화+ㄷ/화+ㅂ받침 등 여러 받침 조합에 다 쓸 수
              있고, 이어붙이는 지점도 두 조각 모두 같은 모음(예: ㅏ)
              으로 끝나고 시작하므로 서로 다른 모음을 섞어 이어붙이는
              것보다 자연스럽게 들립니다. 그래도 없으면 지금처럼
              전부 조각을 이어붙입니다(예: 호+악).

      "syllable_overrides": true
          dedicated_diphthongs를 일반화한 설정 - 이중모음뿐 아니라
          "어떤 음절이든" 통째로 대체할 녹음이 있으면 그걸 우선
          씁니다(받침까지 포함한 완전한 글자 기준). 조각을 이어붙일 때
          이음매가 어색하게 들리는 음절(예: 받침 ㄱㄷㅂ이 있는 "학"은
          크로스페이드 없이 두 조각을 그냥 붙이고, 받침 ㄴㄹㅁㅇ이 있는
          "반"은 공용 받침 조각과 크로스페이드함)을 하나씩 골라서
          고쳐 녹음할 때 씁니다. VoiceRecorder.exe에서 이미 만든
          pieces 목소리를 열면 "특정 음절 다시 녹음 (전체 대체)" 칸이
          나타나 이 설정을 자동으로 켜줍니다 - bank.json을 직접
          고칠 필요 없습니다.
          두 설정을 같이 켜면 3단계로 대체됩니다: ①완전한 음절 대체
          (syllable_overrides) -> ②모음 부분만 대체 + 공용 받침
          (dedicated_diphthongs) -> ③기존처럼 전부 조각을 이어붙임.

      "preserve_consonant_ui": true
          자음 뒤 ㅢ는 표준 발음법상 [ㅣ]로 소리 나므로(희망 -> 히망)
          기본적으로는 조각을 찾을 때도 그렇게 처리합니다. 자음+ㅢ
          음절(예: 씌)을 구분해서 녹음/재생하고 싶다면 이 설정을
          켜세요 - 대부분의 목소리는 이미 있는 조각(예: 씌 -> sseu +
          i)만으로 바로 동작하므로 추가 녹음이 필요 없는 경우가
          많습니다. (참고: "나의" 같은 조사 '의'를 [에]로 읽는 것은
          완전히 다른 문제로, 문장에서 그 ㅢ가 조사인지 아닌지
          구별해야 해서 지원하지 않습니다 - 구개음화(굳이->구지)를
          지원하지 않는 것과 같은 이유입니다.)

  full-syllable (완전한 음절 통째로)
      한글 음절 하나하나를 통째로 녹음하는 방식입니다. 조각을 이어붙이지
      않으므로 가장 자연스럽게 들리지만, 녹음할 양이 훨씬 많습니다.
      "필요한" 음절은 한글 11,172자 전체가 아니라 실제로 조회되는
      2,904개뿐입니다 (쟈/져/쳐처럼 발음 규칙으로 항상 다른 음절로
      먼저 합쳐지는 것은 애초에 찾아지지 않으므로 녹음해도 쓰이지
      않습니다) - "preserve_consonant_ui": true 를 켜면 자음+ㅢ
      음절도 구분해서 세므로 3,048개가 됩니다.
      settings에 "fallback_bank": "default" 처럼 대체 목소리(pieces
      방식이어야 함)를 지정하면, 이 목소리에 없는 음절은 그 대체
      목소리로 대신 읽어줍니다 - 그래서 전부 다 녹음하지 않아도 바로
      쓸 수 있습니다.

      py tts.py --voice narrator2 --check
      로 확인하면 몇 개나 직접 녹음되어 있고 나머지가 어느 목소리로
      대체되는지 보여줍니다.

  diphone (온셋+중성 · 중성+받침 조각)
      pieces와 full-syllable 사이의 절충안입니다. 초성+중성("온셋+
      중성 조각", 예: 가) 조합 하나와 중성+받침("중성+받침 조각", 예:
      안) 조합 하나, 총 두 조각만으로 어떤 음절이든 만듭니다 - 받침이
      없으면 온셋+중성 조각 하나만 그대로 쓰고, 받침이 있으면 두
      조각을 자연스러운 크로스페이드로 붙입니다. pieces처럼 모음을
      쪼개서 근사하지 않고, full-syllable처럼 음절마다 따로 녹음하지도
      않아서, 약 510개(자음+ㅢ 구분 시 528개) 녹음만으로 pieces보다
      자연스러운 소리를 낼 수 있습니다. settings의 "fallback_bank"는
      full-syllable과 동일하게 동작하되, 온셋+중성/중성+받침 둘 중
      하나라도 없으면 그 음절 전체를 대체 목소리로 읽어줍니다(일부만
      대체하지 않음).

세 종류 모두 VoiceRecorder.exe 에서 새 목소리를 만들 때 고를 수 있습니다
(VOICE_RECORDER_README.txt 참고) - 한 번 만든 뒤에는 종류를 바꿀 수
없습니다 (이미 녹음된 파일들이 이전 방식의 이름 규칙을 따르고 있어서,
바꾸면 그 파일들을 못 찾게 됩니다).

audio 항목에는 이 목소리에만 적용할 음량/이음매 타이밍 설정을 넣을 수
있습니다 (전역 기본값을 목소리별로 덮어씀):

    {
      "audio": {
        "normalize_target_rms": 3500,
        "normalize_max_gain": 8.0,
        "normalize_peak_limit": 32000,
        "silence_threshold": 250,
        "crossfade_fraction": {"diphthong": 0.50, "coda": 0.25, "diphone": 0.25},
        "crossfade_min_ms": 20,
        "crossfade_max_ms": 150,
        "coda_max_ms": 120,
        "coda_tail_fade_ms": 20,
        "default_stop_gap_ms": 40
      }
    }

전부 선택 사항이고, 적지 않은 항목은 지금까지 쓰던 기본값을 그대로
씁니다. 다르게 녹음된 목소리(마이크 게인이 다르다거나, 화자의 받침
발음이 유독 길거나 짧다거나)에 맞게 조정하고 싶을 때 씁니다. 지금은
직접 bank.json 파일을 편집해서 씁니다 - 고급 설정 GUI에는 아직
이 설정을 편집하는 화면이 없습니다.

새 목소리를 추가했다면(그리고 bank.json도) sync-sound-assets.bat 을
다시 실행해야 Android 앱과 웹 버전에도 반영됩니다. Android 앱과 웹
버전은 아직 pieces 방식만 재생할 수 있습니다 - full-syllable, diphone
등 다른 종류의 목소리는 목록에 아예 나타나지 않습니다(오류 없이 조용히
숨겨짐). CLI와 데스크톱 앱(gui.py/KoreanTTS.exe)은 세 종류 모두
재생됩니다.


4-3) 완전한 음절 파일 이름 규칙
--------------------------------
full-syllable, diphone 목소리(그리고 4-2)의 dedicated_diphthongs /
syllable_overrides 설정)에서 쓰는 파일 이름은 그 음절의 유니코드
코드포인트를 16진수 4자리로 쓴 것입니다
(예: 가 -> ac00.wav, 각 -> ac01.wav). 한글 글자를 파일 이름으로 그대로
쓰지 않는 이유는 macOS와 Windows/Linux가 한글 자모를 다르게 정규화해서
저장하는 경우가 있어(같은 글자가 다른 바이트로 저장됨) 파일을 못 찾는
문제가 생길 수 있고, 웹 버전에서 파일을 받아올 때도 URL 인코딩 문제가
생기기 쉽기 때문입니다. VoiceRecorder.exe 는 파일 이름을 직접 보여주지
않고 항상 실제 읽어야 할 글자만 크게 보여주므로, 이 규칙을 몰라도
사용하는 데는 문제없습니다.

diphone의 "중성+받침" 조각도 같은 규칙을 쓰되, 실제로 녹음할 때는 그
받침 앞에 초성이 없는(ㅇ) 채로 읽습니다 - 예를 들어 "안"(ㅇ+ㅏ+ㄴ)이면
그 발음 그대로가 "중성 ㅏ + 받침 ㄴ" 조각이 되어 an.wav가 아니라
해당 코드포인트의 hex 이름으로 저장됩니다. VoiceRecorder.exe가 diphone
목소리를 만들 때 보여주는 글자가 정확히 그 발음이므로, 이 규칙도
외울 필요는 없습니다.


====================================================
자연스러운 발음 처리
====================================================

글자 하나하나를 따로 읽지 않고, 앞뒤 글자가 만날 때 실제로 어떻게 소리 나는지
표준 발음법대로 처리합니다. -p 옵션으로 실제 어떻게 발음될지 텍스트로 미리
확인할 수 있고, 규칙은 한 문장 안에서 여러 개가 이어서 적용됩니다
(예: 협력을 -> 혐녀글, 국물이 -> 궁무리).

연음화 (받침이 뒤 모음으로 이동)
    옷이     -> 오시   (받침 ㅅ이 다음 음절로 이동)
    좋아요   -> 조아요  (받침 ㅎ은 모음 앞에서 사라짐)
    값이     -> 갑시   (겹받침은 둘로 나뉘어 하나씩 처리)
    강아지   -> 강아지 (받침 ㅇ은 다음 음절로 넘어가지 않음, 원래 그대로)

비음화 (받침 ㄱㄷㅂ + ㄴㅁ -> ㅇㄴㅁ)
    국물     -> 궁물
    밥물     -> 밤물
    닫는다   -> 단는다

ㄹ 관련 비음화 · 유음화
    협력     -> 혐녁   (받침 ㄱㄷㅂ + ㄹ -> 둘 다 비음화)
    담력     -> 담녁   (받침 ㅁㅇ + ㄹ -> ㄹ만 ㄴ으로)
    신라     -> 실라   (ㄴ+ㄹ / ㄹ+ㄴ -> ㄹㄹ, 일반적인 경우만)

격음화 (ㅎ + 예사소리 -> 거센소리)
    좋다     -> 조타
    많고     -> 만코
    각하     -> 가카

경음화 (받침 ㄱㄷㅂ 뒤 예사소리 -> 된소리)
    국밥     -> 국빱
    학교     -> 학꾜
    학생     -> 학쌩
    잡지     -> 잡찌

ㅈㅉㅊ 뒤 반모음 탈락 (한 음절 안에서 판단, 앞뒤 글자 필요 없음)
    가져요   -> 가저요
    쟤       -> 재
    다쳤어요 -> 다처써요
    (ㅈ,ㅉ,ㅊ은 이미 구개음이라 뒤에 오는 ㅑㅒㅕㅖㅛㅠ의 반모음이 따로
     들리지 않습니다 - 표준발음법 제5항 다만1)

ㅢ의 단모음화 (한 음절 안에서 판단)
    희망     -> 히망
    무늬     -> 무니
    띄어쓰기 -> 띠어쓰기
    의사     -> 의사   (첫소리가 ㅇ이면 그대로, 표준발음법 제5항 다만3)

띄어쓰기나 문장부호를 사이에 두면 위 규칙 중 앞뒤 글자가 만나야 적용되는
것들(연음화/비음화/유음화/격음화/경음화)은 적용되지 않습니다 (실제 발음
규칙과 동일). ㅈㅉㅊ 뒤 반모음 탈락과 ㅢ의 단모음화는 한 글자 안에서만
판단하므로 이 제약과 무관하게 항상 적용됩니다.

다루지 않는 규칙 (사전/형태소 정보가 있어야 판단 가능한 것들)
    - 구개음화: 굳이 -> 구지 는 처리되어야 하지만 마디(형태소 경계가 없는
      단어) 는 구지로 잘못 바뀌면 안 되는데, 표면 글자만 보고는 구별할 수
      없습니다.
    - 사잇소리 경음화: 손+가락 -> 손까락 같은 경우. 받침이 ㄱㄷㅂ이 아니라
      합성어라는 정보가 있어야 판단 가능합니다.
    - 유음화의 한자어 예외: 의견란 -> 의견난 (의결란이 아님) 같은 경우.

이 규칙들을 직접 구현하기 전에 파이썬 라이브러리 korean_romanizer 를 검토해
봤습니다 (순수 파이썬이라 g2pK처럼 자바/mecab이 필요 없어서 유력한 후보였음).
실제로 설치해서 테스트해보니 비음화(국물 -> 국물, 안 바뀜)가 아예 빠져 있고
구개음화는 틀리게 구현되어 있었습니다(해돋이 -> 해도디, 해도지가 맞음). 격음화만
정확히 동작했습니다. 이런 이유로 검증 가능한 규칙만 직접 만들어 넣는 쪽을
택했습니다.


====================================================
음질 처리
====================================================

음량 자동 보정
--------------
sound 폴더의 268개 파일은 녹음 상태가 제각각이라 RMS 음량 기준으로 최대
45배까지 차이가 났습니다 (어떤 글자는 거의 안 들리고 어떤 글자는 상대적으로
큼). 재생/저장 시 각 조각을 기본적으로 음량 정규화합니다:

    - 목표 음량(RMS)에 맞춰 조용한 조각은 키우고 큰 조각은 줄입니다.
    - 너무 조용한 조각(짧은 무음/노이즈)을 과하게 키워 잡음이 커지지 않도록
      증폭 배율에 상한을 둡니다.
    - 이미 큰 조각을 키우다 클리핑(찢어짐)되지 않도록 피크 상한도 둡니다.
    - 각 조각 앞뒤의 무음 구간도 잘라내어, 이어붙였을 때 쉬는 길이가
      --gap 값 그대로 나오도록 합니다.

목표 음량은 기본적으로 꽤 높게 잡혀 있습니다 (원래보다 +4dB 더 큼 - 268개
파일 중 조용한 쪽 3%(예: beu.wav) 정도만 증폭 배율 상한에 걸려 목표보다
조금 작게 나오고, 나머지는 목표 음량에 맞춰집니다). 대부분의 기기에서
음량을 따로 올리지 않아도 잘 들리도록 하기 위한 것입니다.

원본 그대로 듣고 싶으면 --no-normalize (대화형은 :norm) 로 끌 수 있습니다.

이중모음·받침 크로스페이드
--------------------------
sound 폴더에는 "초성+모음" 조각과 "모음+예사받침" 조각(예: 압 -> "ab" 하나)만
녹음되어 있고, 이중모음(ㅘㅝㅢ 등)이나 유성 받침(ㄴㄹㅁㅇ)은 그런 조각이 없어서
대신 다른 조각 두 개를 이어 붙입니다. 문제는 유성 받침용 낱글자 조각("n","m",
"l","ng")이 원래 온전한 한 음절 길이(150~230ms)로 녹음되어 있어서, 그냥 이어
붙이면 그 글자 하나가 음절 두 개 분량으로 늘어져 들립니다.

    화 -> "ho"+"a" 를 그냥 이어 붙이면 380ms, 실제로는 한 음절이어야 함
    안 -> "a"+"n"  마찬가지로 490ms

한 글자를 이루는 조각들은 그냥 이어 붙이지 않고 겹쳐서 크로스페이드 합니다
(뒤 조각의 시작과 앞 조각의 끝을 등강도(equal-power) 곡선으로 섞어 자연스럽게
이어지면서 전체 길이도 줄어듭니다):

    - 이중모음(ㅘ/ㅝ/ㅢ 등): 짧은 쪽 길이의 50%까지 겹침 - 모음 두 개가
      섞이는 게 실제 이중모음이 소리 나는 방식과 같아서 더 과감하게 섞습니다.
    - 유성 받침(ㄴㄹㅁㅇ): 짧은 쪽 길이의 25%까지 겹침 - 받침 자음의 특징이
      묻히지 않도록 이중모음보다는 살짝만 섞습니다.
    - 예사받침이 이미 모음과 한 조각으로 녹음된 경우(학 -> "ha"+"ag" 등)는
      원래 문제가 없던 경우라 건드리지 않습니다.

유성 받침 낱글자 조각("n","l","m","ng")은 크로스페이드만으로는 부족할 만큼
길어서, 받침으로 쓰일 때는 재생 전에 80ms로 잘라내고 그 끝을 짧게
페이드아웃합니다. 받침은 모음 뒤에서 뒷모음 없이 바로 끝나야 하므로, 원본을
그대로 쓰는 대신 이렇게 짧은 닫힘 소리만 남깁니다.

크로스페이드 + 받침 자르기를 합치면 실측 기준:

    안 493ms -> 322ms (35%)     반 494ms -> 323ms (35%)
    왕 765ms -> 445ms (42%)     웜 703ms -> 444ms (37%)
    화 382ms -> 322ms (16%, 이중모음만 해당, 받침 없음)

--no-crossfade (대화형은 :cross) 로 끄면 크로스페이드와 받침 자르기를 모두
끄고 예전처럼 그냥 이어 붙입니다. 비율/길이는 korean_tts.py 의
CROSSFADE_FRACTION, CODA_MAX_MS 에서 조정할 수 있습니다.

받침 ㄱㄷㅂ 뒤 간격
--------------------
위의 크로스페이드/받침 자르기가 "너무 긴" 받침(ㄴㄹㅁㅇ) 문제를 다룬다면,
이건 반대 문제입니다: 받침 ㄱ/ㄷ/ㅂ(대표음 기준 - ㅋ,ㄲ,ㅅ,ㅆ,ㅈ,ㅊ,ㅌ,ㅎ,ㅍ
등도 전부 이 셋 중 하나로 합쳐짐)으로 끝나는 글자는 다음 글자로 너무 빨리
넘어가서 급하게 들립니다. 실제 발음에서는 이 받침들이 파열 없이 닫힌
채로 잠깐 멈췄다가 다음 소리로 넘어가는데, 지금까지는 다른 글자 사이와
똑같이 간격 없이 바로 이어 붙이고 있었습니다.

기본적으로 이런 받침 뒤에 40ms 를 추가로 쉬고 다음 글자를 읽습니다
(--stop-gap, 대화형 :stopgap 으로 0~200ms 사이에서 조절, 0이면 끔).
연음화·비음화·경음화 등으로 받침의 실제 발음이 바뀐 경우(예: 국물 ->
궁물, ㄱ이 비음화되어 ㅇ이 됨)에는 바뀐 뒤의 발음 기준으로 판단하므로,
받침이 사라지거나 다른 받침으로 바뀐 경우에는 이 간격이 붙지 않습니다.


====================================================
문제 해결
====================================================

"음성 폴더가 없습니다" 라고 나올 때
    sound.zip 을 이 폴더 안 sound/ 에 풀었는지 확인하세요.
    다른 위치에 있다면 --sound-dir 로 경로를 지정하세요.

한글이 깨져서 나올 때 (cmd 창)
    chcp 65001 을 먼저 실행해서 콘솔 코드페이지를 UTF-8로 바꾸세요.
    (프로그램 자체는 깨진 글자 없이 항상 정상적으로 동작합니다 - 화면
    출력만 깨져 보이는 문제입니다)

재생이 안 될 때
    Windows 는 winsound 로 재생하므로 별도 설치가 필요 없습니다. 다른
    OS 에서는 ffplay(ffmpeg), aplay, paplay 중 하나가 PATH 에 있어야
    합니다. 재생 대신 -o 로 파일만 저장해서 다른 플레이어로 들어도 됩니다.

특정 글자가 안 들릴 때
    py tts.py --check 로 sound/ 에 필요한 268개 조각이 다 있는지
    확인하세요. 빠진 파일이 있으면 목록으로 알려줍니다.


====================================================
파일 구성
====================================================
    tts.py          CLI 프로그램 (이 파일이 진입점)
    korean_tts.py   한글 -> 발음 처리 -> 음성조각 변환 -> wav 합치기.
                    디스코드 봇(main.py)과 이 로직을 공유합니다.
    sound/          음성 조각 268개 (.wav)

발음/조각 변환 규칙과 음질 처리는 korean_tts.py 한 곳에만 있어서, 봇과
CLI 가 항상 똑같이 발음하고 똑같이 들립니다. 디스코드 봇 자체의 설치·실행
방법은 README.txt 를 참고하세요.
